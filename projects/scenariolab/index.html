The problem

Every student asks, “Why do I need to learn this?”, and most never find out. Knowing a subject isn't the same as knowing how to use it at work, where the real skill is the thought process: reading a brief, weighing trade-offs, designing a solution and explaining it so others can build it.

What I built

I took ScenarioLab from idea to working product: the concept, the product and UI design, the whole app, and the pitch. My teammate helped research whether the idea was strong enough.

  • Came up with the concept and designed the learning flow: lecture → tasks → scenario → design → senior review → revision
  • Built the Next.js app end to end: onboarding, lesson and workspace screens, results, and file-explorer style navigation
  • Wrote the Gemini-powered API routes for lecture breakdown, scenario generation, review, hints and mentor chat, each with its own tightly scoped prompt
  • Built the drag-and-drop flowchart editor (React Flow) and AI-generated diagrams (Mermaid), including a diagram for the suggested answer
  • Added mastery memory that tracks weak spots across tasks, and scenarios calibrated to the student's target company
  • Deployed it on Vercel and presented it at the hackathon

How it works

  1. Paste a lecture, syllabus or slides (PDF and PPTX are parsed on the server).
  2. The AI splits the material into tasks, and each becomes a realistic scenario with a role, stakes, constraints and a rubric, tailored to the student's career goal.
  3. The student designs the solution in words, as a drag-and-drop flowchart, or both. No code, so the time goes into thinking and explaining.
  4. An AI “senior” reviews the design against the rubric, with up to 3 rounds to improve before comparing against a suggested answer.
  5. Stuck? Ask for a hint, a simpler version, or chat with one of two mentors: Casey (kind) or Morgan (busy).

The AI is prompted to evaluate, not reveal: the reviewer points at gaps without giving the answer, and the mentor refuses to hand over the solution. Everything is stored in the browser, so there are no accounts and nothing to set up.

One hard problem

Uploads that worked locally but crashed in production

During the hackathon, PDF uploads worked on my machine but returned a 500 error on the deployed site. The PDF library I'd started with, pdf-parse, wraps pdf.js, which pulls in an optional native canvas dependency and a separate worker file. Vercel's serverless bundler didn't reliably include those files, so parsing only failed in production, where the full node_modules isn't there.

I switched to unpdf, a build of pdf.js made for serverless that needs no canvas for plain text extraction, and uploads worked again with no Next.js config workarounds. Around the same time, the Gemini SDK and model we were using were deprecated and every AI call started returning 404s, so I migrated all the routes to the new @google/genai SDK.

Results

The feedback at the hackathon was that ScenarioLab would be genuinely useful for students. The main suggestion was to fact-check scenarios against backup sources, instead of relying only on the uploaded PDF or slides.

What's next

First, acting on that feedback: adding backup sources so scenarios are fact-checked, not built only from the uploaded files.

ScenarioLab fits computer science best today, where we know the professional workflow well. The same pattern of role, constraints, design, senior review and revision applies to any field with a professional practice, so the next step is researching how other fields actually work, so each subject's scenarios and feedback match real practice.
